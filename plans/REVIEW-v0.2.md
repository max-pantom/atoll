# Atoll v0.2 review (`git diff v0.1.0..HEAD`)

Reviewer: Opus 5.5, low effort. Checked against the Shared rules and the Builder A/B prompts in plans/v0.2-prompts.md.

## Blockers

1. **The zsh ping snippet fails on every long command.** `docs/atoll-ping.zsh:20` declares `local status=ok`. In zsh, `status` is a read-only special parameter (an alias of `$?`), so `_atoll_precmd` errors with "read-only variable: status" and never pings. Rename it, for example to `local st=ok`, and update lines 21 and 23.
2. **CI demos for the new activities can trigger the Calendar permission prompt.** `Sources/Atoll/Activities/Calendar/CalendarActivity.swift:66` only skips the prompt when an argument is exactly `--demo`. All the new demos use `--demo=<name>`, so CalendarActivity still calls `requestFullAccessToEvents` on a CI runner. Match `$0.hasPrefix("--demo")` instead, as `QuickCaptureActivity.swift:131` already does.

## Should-fix

1. **The default clipboard hotkey takes over a system shortcut.** `Sources/Atoll/Activities/Clipboard/ClipboardActivity.swift:42-43` sets ⌥⌘V, which is Finder's "Move Item Here". Clipboard is on by default, and `RegisterEventHotKey` grabs the shortcut globally, so moving files in Finder breaks as soon as the app runs. Pick a free default such as ⇧⌘V… or ⌃⌥V, or leave the shortcut unset until the user records one.
2. **Clipboard image handling can block the main thread and use a lot of memory.** `ClipboardActivity.swift:140` reads PNG/TIFF data up to 25 MB on the main thread every time something is copied. 20 such items can hold about 500 MB. `ClipItem.sameContent` (`:30`) also compares full `Data` blobs against every item on each copy. Lower the cap or downsample on ingest, compare by a hash, and move the read off the main run loop where possible.
3. **Main-thread EventKit query.** `Sources/Atoll/Activities/Meeting/MeetingActivity.swift:95-110`: `refreshEvents()` runs `store.events(matching:)` on the main actor every 15 s. That call is synchronous and can be slow on large calendars. Run it on `queue`, as the device checks already are (`:80`).
4. **Main-thread Keychain reads in poll loops and in SwiftUI bodies.** `Sources/Atoll/Activities/DevMode/DevCommon.swift:48-49`: `hasGitHubToken` and `hasVercelToken` call `SecItemCopyMatching` on every Settings render (`Settings/FocusDevSettings.swift:56,78`). `GitHubActionsActivity.swift:36` and `VercelActivity.swift:34` read the Keychain on the main actor on every poll, every 10 to 30 s, even with no token. Cache a "has token" bool when the token is set, and read the token once per loop restart (`tokenVersion` already exists for this).
5. **`NSAppleScript` runs off the main thread.** `Sources/Atoll/Activities/QuickCapture/QuickCaptureActivity.swift:139-144` runs `executeAndReturnError` inside `Task.detached`. `NSAppleScript` is not thread-safe and Apple documents it as main-thread only. It can crash, or fail silently when it runs at the same time as the Music/Spotify AppleScript fallback. Use `NSUserAppleScriptTask`, or run `osascript` through `Process` off the main thread.
6. **Priority: a CI success outranks a meeting heads-up.** `DevCommon.swift:100` gives a finished CI item priority 75, and `TerminalPingActivity.swift:15` gives a ping 80. A meeting heads-up is only 70 (`MeetingActivity.swift:23`) and ties with Battery, where Battery wins because it registered first. A time-critical "meeting in 2 min" pop loses to a green build or a terminal ping. Raise the heads-up to about 85, or drop CI done to about 60.
7. **Pollers keep running after their activity is disabled, and stale state comes back.** `MeetingActivity.swift:61-67` keeps the 2 s timer alive when Meeting is off. `GitHubActionsActivity.swift:20-29` and `VercelActivity.swift:19-28` loop forever, and when disabled they return early without clearing `state`. A running item from before the toggle shows up again when the feature is turned back on. Use `trackEnabled` to start and stop these the way Clipboard and Downloads do, and clear `state` when stopping.
8. **`--demo=` permanently changes user settings.** `Sources/Atoll/Activities/Clipboard/CaptureSettings.swift:73,80,85` call `disabledActivities.remove(...)`, which is persisted. Running a demo locally silently turns on Downloads or Quick capture for good. Bypass the enabled check in demo mode instead of writing to the settings.
9. **Downloads can match a finished download to the wrong file.** `Sources/Atoll/Activities/Downloads/DownloadsActivity.swift:203`: when a partial file disappears and no new file has the same stem, the code falls back to the newest new file. A cancelled download, or any unrelated file saved within 6 s, then gets a "done" pop with the wrong file. Only use the fallback when exactly one new file appeared.

## Nits

1. `Sources/Atoll/Activities/DemoB.swift:2` documents `--demo-expand`, but it is not implemented. Every `--demo=` always blooms after 4 s (`:18-20`).
2. `--demo` coverage: all 8 new activities have a demo (clipboard, capture, downloads, focus, meeting, github, ping, vercel). Check that the CI workflow actually loops over these names. Plain `--demo` still only runs the timer.
3. `Sources/Atoll/Activities/Focus/FocusActivity.swift:131-134`: `Timer.scheduledTimer` already adds the timer to the default mode, and it is then added to `.common` as well. This is harmless, but using `Timer(...)` plus `add(_:forMode: .common)` is cleaner. The same pattern is in `MeetingActivity.swift:63-66`.
4. `FocusActivity.swift:195-198`: `setFocus` runs `shortcuts list` before every `shortcuts run`. Use the cached `FocusShortcuts.shared.installed` value instead.
5. `FocusActivity.swift:250-254`: `FocusLog.add` writes JSON synchronously on the main actor. The file is small, but it is inconsistent with the Clipboard store, which writes on a background queue.
6. `Sources/Atoll/Activities/Meeting/DeviceMonitor.swift:100`: `nonisolated(unsafe) static var savedVolume` is written from `MeetingActivity.queue` only. That is fine today, but a comment, or making it queue-confined, would prevent future races.
7. `Sources/Atoll/Activities/DevMode/TerminalPingActivity.swift:36-44`: any web page or app can open `atoll://notify` and show a fake "ok"/"fail" ping. Consider marking pings from outside the CLI, or require a shared nonce kept in UserDefaults.
8. `Sources/Atoll/Island/IslandDecorations.swift:28`: the mic/camera dot's trailing inset is derived from `idleWidth`. When a wide compact activity owns the island, check that the dot does not overlap trailing content such as Now Playing bars or Timer digits.
9. `Sources/Atoll/Activities/DevMode/DevCommon.swift:113-125`: `CISpinner` uses `TimelineView(.animation)`, which redraws every frame while a run is in progress. That can last minutes. A `rotationEffect` with `.linear.repeatForever` would be cheaper.
10. Visual and motion check: new views use `.island()`, SF Symbols, `.symbolEffect(.replace)` and the existing slot modifiers. No drift from the v0.1 look was found. The Focus ring (3 pt, clipped inside the edge) is the only new on-shell decoration, and the prompt asked for it.
11. Concealed clipboard items: `ClipboardActivity.swift:125-126` correctly skips `ConcealedType` and `TransientType`. Consider also skipping `org.nspasteboard.AutoGeneratedType`.
12. Tokens: GitHub and Vercel tokens go only through `Keychain` (`DevCommon.swift:7-28`). Nothing writes tokens to files or UserDefaults.
